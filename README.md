# InkLeaf

一个把手写批注放在书上的阅读器。读 EPUB / TXT / Markdown / PDF，在正文上直接写、划、注，
写下的东西跟着你读的那句话走 —— 改了字号、重排了版面，笔迹还在原处。

**不申请任何权限。** 没有网络权限，没有存储权限，没有账号。
书和笔记都只在这台设备上。

**下载**：`dist/` 里只有**当前版本**一个发布包（`InkLeaf-<版本>-release.apk`，
Android 12 及以上可直接安装）。`dist/` 不堆历史版本 —— 要旧版去对应的 git tag 取，
理由写在 [`.gitignore`](.gitignore) 那几行注释里。

## 它是什么

- **书封墙的书架**：EPUB 用内嵌封面，读不出封面的自绘一张纸色封面。
- **重排阅读**：字号、行距、页宽、边距、字体（默认 / 宋体 / 等宽）都能调，
  排版是重排的，不是固定版。
- **手写批注**：笔在正文上写，橡皮擦，撤销/重做，墨色八色可选。
- **荧光笔**：笔宽按正文行高走、半透明、叠在字上，涂抹式划重点，不必精确选字。
- **套索与移动**：画个圈选中几笔，拖到别处。移动是**重新锚定**（重新算
  "哪一行 + 行内第几个字"），不是记一个偏移量 —— 所以移动过的笔迹在改字号、
  换横竖屏之后行为与没移动过的一模一样。
- **笔迹不漂**：笔迹记的是"哪一行 + 行内第几个字"，不是"屏幕上第几个像素"。
  换字号、换设备、换横竖屏之后，它还贴在那句话上。
  解不开的时候**宁可不画，也不画错** —— 画错是在告诉用户一个假事实。
- **批注闭环**：高亮、下划线、边注、书签；全文搜索（正文 + 打字批注）；
  笔记清单里每条都标着"现在解开了没有"。
- **看得见的书写**：进度条上标出你写过的地方，笔记清单里每条手写给一张笔迹缩略图。
- **能带走**：单本笔记导出 Markdown，全库导出 zip 档案，换机导入即恢复。
  整页（正文 + 笔迹）也能导出 PNG 或直接分享出去，交给系统相册或第三方 OCR。
- **多种翻页方式**：点屏幕左右热区、音量键（上/下键，可在设置里开关）、
  按住进度条拖动（实时预览目标页，松手跳页）、目录与笔记跳转。
  书写模式下翻页热区可让渡给两侧分区。
- **PDF 也能写**：读 PDF、在 PDF 上写，写回原文件，导出带批注的 PDF。
- **手写识别**：留出可插拔的 OCR 接口，**本版不内置模型** ——
  中文手写模型要十几到几十 MB、准确率不稳，更会破掉上面那句"只在这台设备上"。

## 不想做的

不做云同步、不做账号、不做 TTS、不做社交、不做 AI 摘要。
理由都写在 [`design/M24-收尾审阅.md`](design/M24-收尾审阅.md) 里 ——
一句话：它们要么需要联网，要么会把"自己写"这件事贬值。

## 构建

**要求**

| 项 | 版本 |
| --- | --- |
| JDK | 17 以上（本机用 Android Studio 自带 JBR 25） |
| Gradle | 9.6.0（wrapper 自带） |
| AGP | 9.4.0 |
| Kotlin | 2.4.21 |
| SDK | compileSdk 37 / targetSdk 36 / minSdk 31 |

**命令**

```bash
./gradlew assembleDebug        # 打 debug 包
./gradlew installDebug         # 装到连着的设备上
tools/verify.sh                # 单测 + assembleDebug
tools/verify.sh --device       # 额外跑设备测试（要连着设备）
tools/verify.sh --with-lint    # 额外跑 lint
tools/verify.sh --ci           # 没有预取 robolectric jar 的机器
```

`tools/verify.sh` 是"这个工程现在到底是什么状态"的唯一入口 ——
命令都写在那里，CI 配置只负责调用它。原因写在脚本开头：
远端是内网 Gitea，从开发机上无法确认那台机器有没有注册 runner，
写一份没人执行过的 CI 配置只会得到一份"看起来绿"的假象。

**版本号**：`gradle/libs.versions.toml` 是全工程唯一的版本事实来源，
精确版本、禁止 `+` / `latest.release` / 动态版本。
墨迹编码一旦破坏性升级，历史笔迹可能读不出来，所以版本锁死并用 golden 文件回归。

## 结构

```
app/          Compose 界面层（书架、阅读器、笔记、统计、设置）
core/common   日志、调度器、单位换算
core/data     手写 SQLite（表结构 + 迁移 + DAO）、存储路径、导入导出
core/document 文档解析：EPUB / TXT / Markdown / PDF、排版、全文搜索
core/ink      笔迹：锚点、解析、渲染、命中测试、批注、PDF 写回
core/anchoring 锚点的公共数据结构
core/ui       主题
design/       设计记录与调研（M0–M38）
```

**两条硬规矩，贯穿全工程**

1. **解不开就不画。** 笔迹解不开锚点时不画（`InkResolver` 的硬规则），
   除非它有冻结几何 —— 那种情况下"画在原处"就是唯一正确答案。
2. **坐标只有一套。** 文字与笔迹共用一个 View、一次 `onDraw`、一次画布变换。
   分成两个 View 就必然出现"这帧文字是新排版、笔迹是旧排版"的窗口。

## 测试

- 单测跑在 JVM 上，用 **Robolectric**（native graphics 走真实 Skia，SQLite 是真实实现）。
- **没有虚拟化的机器上设备测试永远跑不起来**，而跑不起来的测试会烂掉 ——
  所以默认门禁是 `tools/verify.sh`（单测 + 构建），设备测试是有设备时再加 `--device`。
- 像素测试证明"画得对"，证明不了"画得省"；耗时断言会被 JIT 抖动打脸。
  性能用"渲染调用次数"这类可确定的口径断言。

## 分支

- `main` —— 主开发线。
- `penengine` —— 小米 PenEngine 笔迹预测（幽灵尾巴）。引擎在小米系统服务里，
  需要小米开发者平台授权包名/签名；预测点只参与显示、永不写入笔迹数据，
  任何鉴权或运行时失败都静默降级为无预测。核心层只认识中立的
  `StrokePredictor` 接口，供应商实现关在 `:app`。
